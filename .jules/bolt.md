## 2024-05-19 - Set Precomputation & Generator Expressions over List Comprehensions for Membership Tests
**Learning:** Found several instances in the `cephadm` module (specifically `schedule.py` and `serve.py`) where list comprehensions were used inside loop conditional membership tests (e.g. `if x not in [y.attr for y in elements]`). This is an O(N*M) anti-pattern that constructs an entire list on each iteration, causing significant overhead in a highly looped/scheduled service manager codebase.
**Action:** Always extract static transformations (like `[dh.hostname for dh in draining_hosts]`) out of loops and convert them to O(1) Sets before the loop execution. If an extraction is difficult or elements are dynamic, replace list comprehensions with `any()` and a generator expression (e.g., `any(d.name == slot.name for d in daemons_to_remove)`) to allow short-circuiting and avoid intermediate memory allocations.
