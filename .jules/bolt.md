## 2024-08-10 - [O(N*M) lookups in list comprehensions and unnecessary materializations]
**Learning:** We found instances in `cephadm` of O(N*M) list lookups inside list comprehensions (e.g. `[h for h in hosts if h.name not in [dh.name for dh in draining_hosts]]`), where an inner list was recalculated on every iteration of the outer list. Additionally, there were checks like `hostname in [h.hostname for h in self.get_unreachable_hosts()]` which build temporary lists just to perform an existence check. Python generator expressions with `any()` enable early exit and avoid allocations, and using pre-calculated sets for lookups converts $O(N^2)$ to $O(N)$.
**Action:** When filtering objects or checking existence over iterables, use pre-calculated Sets for O(1) membership checks to avoid nested lists, and always prefer generator expressions with `any()` for simple containment tests instead of materializing intermediate lists.
