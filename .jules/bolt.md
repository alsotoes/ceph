## $(date +%Y-%m-%d) - Optimize set lookups in list comprehensions
**Learning:** Using `not in [...]` inside a list comprehension creates the list on every iteration, leading to O(N*M) time complexity. This is especially true for list comprehensions with `for ... in ...` used as the right-hand operand to `in` or `not in` operators. This can cause significant slowdowns when both lists are large.
**Action:** When filtering a list by checking if elements are in (or not in) another collection, precompute the collection as a `set` *outside* the loop or list comprehension. This changes the lookup time to O(1) and the overall time complexity to O(N + M). This must be done outside the loop to be effective. For very simple structures, we can avoid set overhead by using short-circuit evaluation like `any(...)`.
